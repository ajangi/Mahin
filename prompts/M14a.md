# M14a Cloud Agent Prompt — Design Foundations

## Authority
Follow `AGENTS.md`, `docs/PRD.md`, `docs/DECISIONS.md`, `docs/DESIGN_SYSTEM.md`, `docs/ILLUSTRATION_SYSTEM.md` and `docs/PROGRAM_V2_PLAN.md` (§3 Quality bar). Read `docs/handoffs/M13_HANDOFF.md` first. This prompt scopes the current implementation; the PRD remains authoritative.

## Scope
M14a builds the foundations every later V2 milestone uses. It has **no visible navigation or screen-layout change**.

1. **Screen spec framework.** Create `docs/design/screens/TEMPLATE.md` (regions, states: empty/loading/populated/error/offline, copy keys, tokens, motion, a11y, golden list). Write specs for **shell**, **Settings**, **Today**, **Calendar** and **Log**; these are implemented in M14c, M15 and M16. The owner approves specs at PR review.
2. **Dark health/status colour variants.**
   - Propose dark values for `health.period`, `health.fertility`, `health.ovulation`, `health.pregnancy`, `status.positive`, `status.warning`, `status.critical`.
   - Add them to the dark table in `docs/DESIGN_SYSTEM.md`, the `dark` object in `design/tokens.json`, and `REQUIRED_DARK` in `scripts/check_design_tokens.py`.
   - Wire them into `MahinColors`/`MahinTheme` dark scheme.
   - Write `docs/adr/0020-dark-semantic-colours.md` with the values, contrast results and rationale.
   - **Light and brand tokens stay unchanged.** The owner approves the dark colours at PR review.
3. **Contrast tests.** Add automated tests (Kotlin unit test in `core:designsystem`, and/or an extension of `check_design_tokens.py`). They check each dark semantic colour against `surface.background`, `surface.default` and `surface.elevated`: ≥ 3:1 for non-text graphics, and ≥ 4.5:1 wherever the token is used as text.
4. **Motion tokens.** Add durations and easings to `design/tokens.json` and `MahinTokens`. Add a `LocalReducedMotion` composition local that honours the system animator-duration scale / remove-animations setting, with unit tests.
5. **Numeric Display role.** Implement the existing `NumericDisplay` typography role (Vazirmatn per ADR 0004) for large tracking numbers (`۲۸`, `هفته ۲۱`) with Persian digits and tabular figures where the font supports them.
6. **Full-screen golden harness.**
   - A reusable helper (e.g. in `core:testing`) that renders a whole screen in fa-IR RTL across light/dark × font scale 1.0/1.3 and records via Roborazzi.
   - Run it against today's screens: Today, Calendar, Log, History, Onboarding welcome, Cycle insights, Learn, Pregnancy hub, with synthetic fixture data.
   - Goldens live in each module's Roborazzi output directory, `<module>/src/test/screenshots/` (the single golden location for V2).
   - Wire `verifyRoborazziDebug` into the `android` job in `.github/workflows/ci.yml` with a documented tolerance (shared `RoborazziOptions` with `CompareOptions(changeThreshold = …)`). Document how to re-record locally.
7. **Benchmark module skeleton.** Add a `:benchmark` (`com.android.test`) module with a macrobenchmark startup test, a Today first-frame test and a baseline-profile generator. CI compiles it only (no device on `ubuntu-latest`).

## Execution rules
- Implement **M14a only**. Do not change navigation, screen layouts or copy.
- Do not change light or brand tokens. Any brand-token change needs a separate ADR and owner approval.
- No hex colours in feature code; `check_design_tokens.py` must keep passing.
- Preserve all earlier milestone behaviour and migrations.
- Never invent medical claims/content. Golden fixtures use synthetic data clearly marked non-real.
- Keep Persian/RTL, offline-first behaviour, accessibility, privacy and sensitive-data redaction intact.
- Run relevant format, lint, static analysis, unit/UI tests and builds before completion.

## Out of scope
- Icons and illustrations (M14b).
- Bottom bar, top app bar and Settings screen (M14c).
- Today/Calendar/Log redesign (M15/M16).
- Running benchmarks in CI; real-device performance targets.
- Backend, OpenAPI, migrations.

## Acceptance criteria
- `docs/design/screens/TEMPLATE.md` plus shell, Settings, Today, Calendar and Log specs exist.
- Dark semantic tokens are present in `DESIGN_SYSTEM.md`, `design/tokens.json`, `REQUIRED_DARK` and the Android dark theme. ADR 0020 is written. Light/brand tokens are unchanged (diff-verified).
- Contrast tests pass for every dark semantic colour against all three dark surfaces.
- Motion tokens and `LocalReducedMotion` exist with tests.
- `NumericDisplay` is used in at least the design-system showcase/golden and renders Persian digits.
- The golden harness produces light/dark × 1.0/1.3 RTL captures for the listed screens under `<module>/src/test/screenshots/`.
- CI runs `verifyRoborazziDebug` and passes on the PR head.
- `:benchmark` compiles in CI. If an emulator is available to the agent, startup numbers are reported in the handoff; otherwise the handoff says they were not measured.
- All existing checks from the M13 handoff command list pass.
