# M16 Cloud Agent Prompt — Logging Experience Overhaul

## Authority
Follow `AGENTS.md`, `docs/PRD.md` §7.2–7.3, §8 and §9.4, `docs/DESIGN_SYSTEM.md`, `docs/PROGRAM_V2_PLAN.md` §3. Read `docs/handoffs/M15_HANDOFF.md` and the Log spec from M14a. This prompt scopes the current implementation; the PRD remains authoritative.

## Problem
Logging is a long form. The core habit loop of a tracker is logging fast, every day.

## Scope
- **Day editor bottom sheet** opened from Today quick-log, the calendar day sheet and the Log tab. Sections are icon grids using M14b icons:
  - period/flow, symptoms, mood, pain, discharge/cervical mucus, TTC tests, medication, notes — on by default as today;
  - sexual activity (see below);
  - lifestyle modules: sleep, exercise, water, stress — **off by default** (PRD §7.3). The user can enable each from the editor's "manage categories" or Settings.
- **Sexual activity is an explicit opt-in category** (PRD §7.3). It is **hidden** (not merely collapsed) until the user enables it. The enabling step explains what is stored and that it never appears in analytics or notifications. Disabling hides it again and keeps existing entries unless the user deletes them.
- **One-tap toggles** with immediate local save, an undo snackbar and a confirmation animation that respects `LocalReducedMotion`. No save button for the common case.
- **Pain** keeps the PRD model: location plus severity on a **0–10 scale** (stepper or slider with Persian digits) and an optional note.
- **Personalised ordering**: the user can pin/reorder enabled categories. Optional most-used-first ordering uses a local-only, deterministic rule that is unit-tested and never leaves the device.
- **Custom symptoms/tags — local-only.** Stored in Room via a migration. **Not** added to the sync outbox, OpenAPI or data export in M16. Syncing/exporting them is a later owner decision (plan §7).
- **Period range editing**: set start/end from the calendar, plus merge/split of mistaken ranges (PRD §7.2).
- **Pregnancy mode** reuses the editor with pregnancy-relevant categories (PRD §9.4).
- Notes keep their existing encryption and privacy guarantees.

## Execution rules
- Implement **M16 only**.
- Room changes are additive migrations with migration tests. No destructive schema edits.
- **No sync, OpenAPI or export changes.** If a requirement seems to need one, STOP that portion and record it in the handoff.
- No symptom, mood, flow, pain, discharge, test, sexual-activity or note values in analytics, logs, crash metadata or notifications.
- Keep RTL, accessibility and offline behaviour intact.
- Run relevant format, lint, static analysis, unit/UI tests and builds before completion.

## Out of scope
- Syncing or exporting custom tags and category preferences.
- New log categories beyond PRD §7.3 / §9.4.
- Insights changes.

## Acceptance criteria
- **Logging effort (UI test):** from Today, 1 tap opens the day editor, then each item (period started, a symptom, a mood) is 1 tap. No save button and no modal for these items.
- Sexual activity is absent from the editor by default and appears only after explicit opt-in (UI test). Lifestyle modules are absent by default (UI test).
- Pain records location and a 0–10 severity (unit + UI tests).
- Migration test from the current DB version to the new version, preserving existing logs.
- Unit tests: the sync outbox receives no custom-tag or category-preference changes, and export output is unchanged.
- `android/core/analytics/src/test/kotlin/dev/mahin/core/analytics/SensitiveAnalyticsGuardTest.kt` is extended to cover any new events, and passes.
- Goldens (light/dark × 1.0/1.3, RTL) under `<module>/src/test/screenshots/` for the editor in cycle, TTC and pregnancy modes, the opt-in step and manage-categories. `verifyRoborazziDebug` passes in CI.
- All existing checks pass.
