# M16 Cloud Agent Prompt — Logging Experience Overhaul

## Authority
Follow `AGENTS.md`, `docs/PRD.md` §7.2–7.3, §8 and §9.4, `docs/DESIGN_SYSTEM.md`, `docs/PROGRAM_V2_PLAN.md` §3. Read `docs/handoffs/M15_HANDOFF.md` and the Log screen spec.

## Problem
Logging is a long form. The core habit loop of a tracker is logging fast, every day.

## Scope
- **Day editor bottom sheet** opened from Today quick-log, the calendar day sheet and the Log tab. Sections are icon grids (M14 icons): period/flow, symptoms, mood, discharge, sex/protection (sensitive; collapsed by default), TTC tests, sleep, water, weight, medication, notes.
- **One-tap toggles** with immediate local save, an undo snackbar and a subtle confirmation animation. No "save" button for the common case.
- **Intensity** for symptoms with a long-press or second tap (mild/moderate/severe), without a modal.
- **Personalised ordering**: the user can pin/reorder/hide categories. Most-used items float up using a local-only, deterministic rule that is unit-tested and never sent off-device.
- **Custom symptoms/tags** (local, synced via the existing outbox; schema migration required).
- **Period range editing**: drag or tap to set start/end on the calendar, with merge/split of mistaken ranges (PRD §7.2).
- **Pregnancy mode** reuses the editor with pregnancy-relevant categories.
- Notes keep their existing privacy guarantees (never logged, never in analytics).

## Persistence
Add a Room migration for custom tags and category preferences. Update `SYNC_SPEC.md` and OpenAPI if synced. No destructive schema edits.

## Acceptance
- Common log (period started + 2 symptoms + mood) takes ≤ 3 taps from Today, verified by a UI test.
- Full-screen goldens of the editor in each mode, light/dark, at font scales 1.0 and 1.3.
- Migration test from the current DB version.
- Analytics events (if any) contain no symptom/mood/flow values — enforced by the existing analytics allowlist test.
- All existing checks pass. Handoff and milestone docs written. STOP after M16.
