# M14b Cloud Agent Prompt — Icon Set & Illustration Slot

## Authority
Follow `AGENTS.md`, `docs/PRD.md` §7.3, `docs/DESIGN_SYSTEM.md`, `docs/ILLUSTRATION_SYSTEM.md`, `docs/PROGRAM_V2_PLAN.md` §3. Read `docs/handoffs/M14a_HANDOFF.md` first. This prompt scopes the current implementation; the PRD remains authoritative.

## Scope
1. **Original Mahin icon set** as Android vector drawables in `core:designsystem`, exposed through a typed `MahinIcons` API with stable semantic IDs (e.g. `symptom/cramps/v1`). Visual language follows `ILLUSTRATION_SYSTEM.md`: rounded organic geometry, a consistent 24 dp grid and stroke weight, Mulberry line plus at most one semantic accent via theme tokens, and no embedded text. Families:
   - `nav` — Today, Calendar, Log, Insights, Learn, Pregnancy, Plan, History, Settings/profile.
   - `action` — add, edit, delete, undo, share/export, search, bookmark, close, back (RTL-aware mirroring where directional).
   - `flow` — spotting, light, medium, heavy, very heavy.
   - `symptom` — every PRD §7.3 symptom plus pain.
   - `mood` — every PRD §7.3 mood.
   - `discharge` — dry, sticky, creamy, watery, egg-white/slippery, unusual/other.
   - `tests` — ovulation test (OPK), pregnancy test, BBT.
   - `lifestyle` — sleep, exercise, water, stress, weight, medication/supplement.
2. **Medical-sensitivity rule for icons.** OPK, pregnancy-test and discharge icons must be **abstract and non-anatomical**. Test icons must show **no result lines or result states**. No icon depicts anatomy, bodily fluids or fetal imagery. Do not trace, adapt or reproduce any competitor artwork.
3. **Debug icon catalogue** screen in `app/src/debug/` that renders every icon with its ID in light/dark, plus an **icon-sheet golden** via the M14a harness.
4. **`MahinIllustration(assetId, contentDescription | decorative)`** composable behind the existing `core:media` boundary:
   - Resolves stable semantic IDs to **bundled** vector placeholders only in M14b.
   - Ships clearly labelled neutral placeholder art (abstract shapes in tokens) for empty-state and editorial slots. Each placeholder has metadata `placeholder = true`.
   - **Medical-image gating:** any asset ID in a medical-governed family (`pregnancy/*`, `cycle/education/*`, per `ILLUSTRATION_SYSTEM.md`) renders a neutral frame with no imagery unless its metadata says `approvalStatus = approved`. Placeholders can never satisfy that check.
   - Defines the interface a remote source will implement later. **Remote CMS image loading (Coil) is out of scope and moves to M17.**

## Execution rules
- Implement **M14b only**. Do not change navigation or screen layouts beyond the debug catalogue.
- Icons use theme tokens only; no hex colours in feature code.
- Do not describe the icon set as "non-medical" in docs or code. Borderline icons are listed for clinical review (see handoff).
- Do not download, scrape or trace external imagery or icon packs.
- Preserve earlier behaviour; keep RTL, accessibility and privacy intact.
- Run relevant format, lint, static analysis, unit/UI tests and builds before completion.

## Out of scope
- Using the new icons in production screens (M14c, M15, M16).
- Remote/CMS image loading, caching and Coil (M17).
- Final editorial or medical illustrations.
- Backend, OpenAPI, migrations.

## Acceptance criteria
- Every family above is complete, and each icon is reachable through `MahinIcons` by semantic ID.
- The debug catalogue renders every icon. The icon-sheet golden (light/dark) is recorded under `<module>/src/test/screenshots/` and passes `verifyRoborazziDebug` in CI.
- Each icon has a localized (fa) content description, and decorative usage is supported.
- Unit tests prove the medical gating: medical-family IDs without `approved` metadata render no imagery, and placeholders never count as approved.
- Directional action icons mirror correctly in RTL (golden or test).
- `check_design_tokens.py` and all existing checks pass.

## Required handoff
Create `docs/milestones/M14b.md` and `docs/handoffs/M14b_HANDOFF.md` containing: implemented scope; notable files/modules; migrations (none expected); ADRs; exact commands and results; acceptance criteria status; known limitations; unresolved questions; deferred items; **a list of borderline icons for clinical review before release** (at minimum all `tests/*` and `discharge/*` icons, and any symptom icons touching the body); and the next milestone only (**M14c**). Then STOP.
