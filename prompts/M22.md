# M22 Cloud Agent Prompt — Nutrition Programs

> **GATED.** Requires owner approval (plan §7 item 5) and a qualified dietitian content source. If either is missing, STOP and report.

## Authority
Follow `AGENTS.md`, `docs/PRD.md` §10 and §13, `docs/MEDICAL_CONTENT_GOVERNANCE.md`, `docs/PROGRAM_V2_PLAN.md`. Read the M17a/M17b handoffs and the latest handoff. This prompt scopes the current implementation; the PRD remains authoritative.

## Scope (once approved)
- A CMS `meal_program` type extending the M17 `program` model: days → meals → items (Persian foods, portions). Each program has contraindications, target context (general, PCOS, TTC, pregnancy, lactation, vegetarian/vegan, etc.), reviewer/provenance and risk level. Pregnancy, lactation and PCOS programs are high-risk and require clinician review.
- Admin editors and review screens for meal programs.
- Android: a program catalogue filtered by current mode; onboarding questions limited to what the program needs; a daily plan view; a shopping list; CMS-defined swap alternatives; and local adherence check-offs.
- Premium gating is allowed only for non-essential programs (PRD §13). Safety notices are never paywalled.

## Execution rules
- Implement **M22 only**, and only after the gate is cleared.
- **Agents must not generate diets, meal plans or nutrition guidance as real content.** Seed data is placeholder-marked and excluded from release.
- No calorie targets or nutrition calculations unless the formula comes from reviewed configuration.
- Adherence data is local-only unless a sync spec is approved.
- No diet, weight or adherence data in analytics, logs or notifications.
- Additive migrations; OpenAPI in sync.
- Run relevant format, lint, static analysis, unit/integration/UI tests and builds before completion.

## Out of scope
- AI-generated or personalised-by-model meal plans.
- Calorie or macro tracking beyond what reviewed configuration defines.
- Supplement or medication recommendations.

## Acceptance criteria
- Gate evidence (owner approval and content source) is linked in the handoff.
- Backend tests: unapproved meal programs are never served; high-risk contexts require a clinician reviewer.
- A test asserts that no nutrition formula or threshold is defined in Android code.
- `SensitiveAnalyticsGuardTest` covers any new events.
- Goldens (light/dark × 1.0/1.3, RTL) under `<module>/src/test/screenshots/` for the catalogue, daily plan and shopping list.
- All existing checks pass.

## Required handoff
Create `docs/milestones/M22.md` and `docs/handoffs/M22_HANDOFF.md` containing: implemented scope; notable files/modules; migrations; ADRs; exact commands and results; acceptance criteria status; known limitations; content required before launch; unresolved questions; deferred items; and the next milestone only. Then STOP.
