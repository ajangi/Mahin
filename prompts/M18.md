# M18 Cloud Agent Prompt — Pregnancy Companion Depth

> **To be split before execution** (plan §5): **M18a** covers `care_schedule` and `checklist_template` content types, the pregnancy timeline and the tools hub. **M18b** covers the local-only expense tracker, warning signs/BP flagging, weight chart and kick-counter/contraction-timer polish. Execute one part per PR.

## Authority
Follow `AGENTS.md`, `docs/PRD.md` §9, `docs/MEDICAL_CONTENT_GOVERNANCE.md`, `docs/ILLUSTRATION_SYSTEM.md`, `docs/PROGRAM_V2_PLAN.md` §4. Read the latest handoff and ADR 0011. This prompt scopes the current implementation; the PRD remains authoritative.

## Scope
### M18a
1. **Week-by-week view** in the Pregnancy tab:
   - an illustration slot `pregnancy/fetal-development/week-N/vX`, shown only when CMS metadata is `approved`, otherwise a neutral frame plus text;
   - a size comparison labelled as a playful approximation (PRD §9.1);
   - fetal and maternal summaries from the CMS;
   - swipe between weeks.
2. **`care_schedule` content type** (CMS, reviewed, Iran context): recommended tests/ultrasounds by gestational-week window. It is merged with user appointments on one timeline in the **Plan** tab (M14c). Educational framing ("according to your care plan"), with one-tap "add as appointment".
3. **Tools hub**: due-date and gestational-age calculators (LMP / ultrasound / conception) reusing `domain:pregnancy`. Calculators do not persist anything unless the user starts pregnancy mode through the existing confirmed flow.
4. **Hospital-bag checklist**: a CMS `checklist_template` (reviewed) copied into a **local-only**, user-editable checklist with progress.

### M18b
5. **Pregnancy expense tracker — local-only.** Category, amount in Toman/Rial with Persian digits, Jalali date (Gregorian canonical storage) and an optional note, plus a summary by category. **Not** added to the sync outbox, OpenAPI or data export in M18. Syncing/exporting it is a later owner decision (plan §7).
6. **Warning signs & BP.** A reviewed warning-signs card (CMS) and BP-log flagging that uses **only** reviewed thresholds from CMS/config, with escalation copy to seek care. No risk score, no quiz and no diagnosis.
7. **Weight chart**: user-logged weight over gestational weeks. Reference bands only if reviewed content provides them.
8. **Kick counter and contraction timer** polish to the V2 quality bar (no behaviour change to safety messaging).

## Execution rules
- Implement **one split part (M18a or M18b) per PR**, in order.
- Never hard-code medical thresholds, schedules or warning-sign copy in Android.
- Never silently overwrite an EDD; dating rules stay as in ADR 0011.
- Checklist and expense data are local-only. **No sync, OpenAPI sync or export changes.** If one seems required, STOP that portion and record it in the handoff.
- Additive Room migrations with tests.
- No expense, BP, weight or pregnancy data in analytics, logs or notifications.
- Run relevant format, lint, static analysis, unit/integration/UI tests and builds before completion.

## Out of scope
- Fetal sex prediction and eye-colour prediction (declined pending owner confirmation, plan §7).
- Postpartum and baby features (M19, gated).
- Syncing/exporting checklist or expense data.

## Acceptance criteria
- Calculator results match existing `domain:pregnancy` dating rules (unit tests with fixtures).
- Timeline merge ordering of CMS schedule items and user appointments is unit-tested.
- Expense totals and Persian currency formatting are unit-tested.
- Migration tests for checklist and expense tables.
- Unit tests: the sync outbox receives no checklist or expense changes, and export output is unchanged.
- A test asserts BP thresholds come from the config/CMS source, and that no threshold value is defined in Android code.
- Backend tests: unapproved `care_schedule`/`checklist_template` items are never served. OpenAPI lint passes.
- Goldens (light/dark × 1.0/1.3, RTL) under `<module>/src/test/screenshots/` for the week view, Plan timeline, tools, checklist, expenses and warning signs. `verifyRoborazziDebug` passes.
- All existing checks pass.

## Required handoff
For each part, create `docs/milestones/M18a.md`/`M18b.md` and `docs/handoffs/M18a_HANDOFF.md`/`M18b_HANDOFF.md` containing: implemented scope; notable files/modules; migrations; ADRs; exact commands and results; acceptance criteria status; known limitations; clinical content required before launch; unresolved questions (including expense/checklist sync and export); deferred items; and the next milestone only. Then STOP.
