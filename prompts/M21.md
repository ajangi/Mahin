# M21 Cloud Agent Prompt — Expert Consultation (Async Q&A)

> **GATED.** Expert consultation is a PRD §38 non-goal ("clinician marketplace/telemedicine"). Requires owner approval (plan §7 item 2), a PRD amendment, legal review for Iran, a clinician verification process and M20 payments/identity. If any is missing, STOP and report.

## Authority
Follow `AGENTS.md`, the amended `docs/PRD.md`, `docs/PRIVACY_ENGINEERING.md`, `docs/SECURITY.md` and the threat model. Read `docs/handoffs/M20_HANDOFF.md`. This prompt scopes the current implementation; the PRD remains authoritative.

## Scope (once approved)
- A `consultation` module inside the backend modular monolith (no microservice):
  - specialties as approved (e.g. GP, midwifery, OB/GYN, nutrition, psychology, pediatrics);
  - verified clinician accounts with a licence-verification workflow in admin;
  - question threads with attachments;
  - response-window timers, cancellation/refund states and ratings.
- **Privacy design first**: an ADR covering per-thread encryption at rest, least-privilege clinician access (assigned threads only), audit logging of every access, retention and deletion, and explicit per-question consent before any tracked data is shared into a thread. Sharing is never automatic.
- Android: ask flow (specialty → question → optional selection of logs to share → pay), thread view, discreet notifications and history.
- **Safety**: deterministic emergency keyword/intent detection that routes to emergency guidance immediately, plus a clear statement that the service is not for emergencies.
- A clinician console in admin, with a separate role and MFA required.

## Execution rules
- Implement **M21 only**, and only after the gate is cleared.
- The privacy ADR and threat-model update are approved before thread storage is implemented.
- No consultation content, attachments or shared logs in analytics, logs, crash metadata or notification text.
- AI must not answer consultations or draft clinician replies (DECISIONS: no default chatbot).
- Additive migrations; OpenAPI in sync; payment states reuse the M20 billing boundary.
- Run relevant format, lint, static analysis, unit/integration/UI tests and builds before completion.

## Out of scope
- Live video/voice consultation.
- Prescriptions or medication dosing (PRD §38).
- Public Q&A feeds or community features.

## Acceptance criteria
- Gate evidence (owner approval, PRD amendment, legal review) is linked in the handoff.
- Privacy ADR and threat model are merged.
- Access-control tests prove clinicians cannot read unassigned threads, and admins without the clinician role cannot read thread content.
- Audit-log tests cover every read and write of thread content.
- Payment/refund state-machine tests.
- Emergency detection tests with a fixture set; routing is deterministic.
- Goldens (light/dark × 1.0/1.3, RTL) under `<module>/src/test/screenshots/` for the ask flow and thread view.
- All existing checks pass.
