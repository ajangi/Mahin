> **GATED.** Expert consultation is a PRD §38 non-goal ("clinician marketplace/telemedicine"). Requires owner approval (`docs/PROGRAM_V2_PLAN.md` §7 item 2), legal review for Iran, a clinician verification process and M20 payments. If unapproved, STOP and report.

## Authority
Amended `docs/PRD.md`, `AGENTS.md`, `docs/PRIVACY_ENGINEERING.md`, `docs/SECURITY.md`, threat model. Read `docs/handoffs/M20_HANDOFF.md`.

## Scope (once approved)
- Backend `consultation` module inside the modular monolith (no microservice): specialties (GP, midwifery, OB/GYN, nutrition, psychology, pediatrics, subject to approval), verified clinician accounts with licence-number verification workflow in admin, question threads with attachments, SLA timers (e.g. the response window shown to users), cancellation/refund states, ratings.
- **Privacy design first**: an ADR covering encryption at rest per thread, clinician least-privilege access (only assigned threads), audit logging of every access, retention/deletion, and explicit user consent before any tracked data is shared into a thread. Sharing is never automatic.
- Android: ask flow (specialty → question → optional share of selected logs → pay), thread view, notifications with discreet wording, and history.
- **Safety**: emergency keyword/intent detection is deterministic and routes to emergency guidance immediately. The product states clearly that it is not for emergencies.
- Clinician console in admin (separate role, MFA required).

## Acceptance
Threat model + privacy ADR approved; access-control tests prove clinicians cannot read unassigned threads; audit log tests; payment-state machine tests; full-screen goldens; handoff. STOP after M21.
